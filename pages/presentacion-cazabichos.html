¿Qué vamos a construir? 🎯

Un sistema de registro y control de bichos para una app llamada "Cazabichos".

Todo organizado con funciones bien definidas: menú interactivo, validaciones, decisiones y operaciones sobre datos.

El menú que debemos implementar 📋

Menú ========== MENÚ PRINCIPAL ========== 1. Agregar bicho 2. Buscar bicho 3. Eliminar bicho 4. Actualizar estados 5. Mostrar bichos 6. Salir =====================================

El menú se muestra después de cada acción y se repite hasta que el usuario elige "Salir".

⚠️

Restricción importante del menú

⚠️ El menú requiere dos funciones separadas:

📄 Función 1

mostrar_menu()
Solo imprime las opciones.
No recibe nada, no retorna nada.

+

📥 Función 2

leer_opcion()
Lee y retorna la opción validada.
No recibe nada, retorna int.

¿Qué es un "bicho"? 🐛

Cada bicho es un diccionario con 4 campos:

🏷️
"especie"
str
📏
"tamaño"
int
⚠️
"peligrosidad"
float
🚨
"peligroso"
bool

Restricciones de cada campo 🔒

Campo Tipo Restricción
"especie" str No vacío ni solo espacios en blanco.
"tamaño" int Número entero mayor que cero.
"peligrosidad" float Decimal entre 1.0 y 10.0 (incluidos).
"peligroso" bool Inicia en False. No se pide al usuario.
🚨

Regla del campo "peligroso"

El campo "peligroso" nunca se solicita al usuario. El sistema lo asigna automáticamente como False al registrar.

Su valor puede cambiar a True cuando se ejecute la Opción 4 (Actualizar estados), si la peligrosidad del bicho es ≥ 7.0.

Ejemplo {"especie": "Mariquita", "tamaño": 1, "peligrosidad": 2.0, "peligroso": False}

Estructura general de datos 📦

Los diccionarios se guardan dentro de una lista.

La lista comienza vacía y se llena a medida que se registran bichos.

Python # Al inicio del programa principal: lista_bichos = [] # Después de agregar bichos, se ve así: lista_bichos = [ {"especie": "Escarabajo", "tamaño": 15, "peligrosidad": 8.5, "peligroso": False}, {"especie": "Mariquita", "tamaño": 1, "peligrosidad": 2.0, "peligroso": False} ]

¿Qué debe hacer cada opción? (1-3)

Opción Requisito del enunciado
1. Agregar Pedir especie, tamaño y peligrosidad. Validar cada dato. Solo si todos son válidos, crear el diccionario y agregarlo.
2. Buscar Pedir especie. Buscar coincidencia exacta. Mostrar posición y datos, o informar que no existe.
3. Eliminar Pedir especie. Usar la misma función de búsqueda de la opción 2. Si existe, eliminar; si no, informar.

¿Qué debe hacer cada opción? (4-6)

Opción Requisito del enunciado
4. Actualizar Recorrer todos los bichos. Si peligrosidad ≥ 7.0 → True, si no → False.
5. Mostrar Primero llamar a actualizar estados (Opción 4), luego recorrer e imprimir con formato.
6. Salir Terminar limpiamente: "Gracias por usar el Cazabichos. ¡Hasta la próxima expedición!"
⚠️

Restricción: Opción 1 — Agregar

⚠️ Se debe definir una función de validación distinta para cada campo (especie, tamaño, peligrosidad).

Los mensajes de error se muestran en la función de agregar, no dentro de las funciones de validación.

Si algún dato no cumple su condición, no se registra al bicho. Solo cuando todos son válidos se crea el diccionario.

🔍

Restricción: Opción 2 — Buscar

La función de búsqueda recibe la lista y la especie como parámetros.

Retorna la posición (índice) del registro encontrado, o -1 si no existe.

⚠️ Es el programa principal quien decide qué hacer con el resultado. La función no imprime nada.

Restricción: Opción 5 — Formato 📄

La salida debe verse exactamente así:

Salida === LISTA DE BICHOS === Especie: Escarabajo Rinoceronte Tamaño: 15 Peligrosidad: 8.5 Estado: PELIGROSO ******************************************** Especie: Mariquita Tamaño: 1 Peligrosidad: 2.0 Estado: NO PELIGROSO *********************************************

Pseudocódigo

El último paso antes de escribir Python

Ciclo principal 🔄

Requisito: El menú se repite hasta que el usuario elige salir.

Pseudocódigo crear lista_bichos = [] mientras True: mostrar_menu() opcion = leer_opcion() si opcion == 1: agregar_bicho(lista_bichos) sino si opcion == 2: buscar... sino si opcion == 3: eliminar... sino si opcion == 4: actualizar_estados(lista_bichos) sino si opcion == 5: mostrar_bichos(lista_bichos) sino si opcion == 6: imprimir "Adiós" break

Buscar y Eliminar 🔍🗑️

Requisito: Es el programa principal quien decide qué hacer con la posición retornada.

Pseudocódigo # Opción 2 — Buscar esp = pedir especie pos = buscar_bicho(lista_bichos, esp) si pos == -1: imprimir "No encontrado" sino: imprimir datos de lista_bichos[pos] # Opción 3 — Eliminar (reutiliza la búsqueda) esp = pedir especie pos = buscar_bicho(lista_bichos, esp) # ¡misma función! si pos == -1: imprimir "No se encuentra registrado" sino: lista_bichos.pop(pos)

Validaciones ✅

Requisito: Las validaciones solo retornan True/False. No imprimen errores.

Pseudocódigo def validar_especie(especie): cadena = especie.strip() si cadena es vacía: retornar False sino: retornar True def validar_tamano(tamano): si se puede convertir a entero y es > 0: retornar True sino: retornar False def validar_peligrosidad(valor): si se puede convertir a float y 1.0 ≤ valor ≤ 10.0: retornar True sino: retornar False

Agregar bicho ➕

Requisito: Si algún dato falla, no se registra al bicho. Solo cuando todos son válidos se crea el diccionario.

Pseudocódigo def agregar_bicho(lista): pedir especie si NO validar_especie: imprimir error y return pedir tamaño si NO validar_tamano: imprimir error y return pedir peligrosidad si NO validar_peligrosidad: imprimir error y return # Solo si TODO es válido: bicho = {especie, tamaño, peligrosidad, "peligroso": False} lista.append(bicho)

Buscar y Actualizar (funciones) 🔄

Requisito: buscar retorna posición o -1. Actualizar recorre toda la lista según peligrosidad ≥ 7.0.

Pseudocódigo def buscar_bicho(lista, especie): para i desde 0 hasta len(lista): si lista[i]["especie"] == especie: retornar i retornar -1 def actualizar_estados(lista): para cada bicho en lista: si bicho["peligrosidad"] >= 7.0: bicho["peligroso"] = True sino: bicho["peligroso"] = False
🤔

Pregunta para la clase

¿Por qué buscar_bicho() retorna la posición y no el diccionario del bicho?

✅ Respuesta:

Porque la posición sirve para dos cosas:

📍 Acceder al bicho: lista[pos]

🗑️ Eliminarlo: lista.pop(pos)

Si retornara el diccionario, ¡no podríamos hacer pop() fácilmente!

🤔

Pregunta para la clase

Si agregar_bicho() modifica la lista con .append(),
¿necesitamos hacer return lista?

✅ Respuesta: NO

Las listas son mutables en Python.

Cuando la función recibe la lista como parámetro y le hace .append(), el cambio ya queda hecho en la lista original del programa principal.

No es necesario retornarla. 🎯
