🧰 Mini-taller: Funciones en Python

De cero a sistema completo — 15 patrones clave y 31 ejercicios progresivos. Todo lo que necesitas para dominar funciones y prepararte para el examen.

Introducción: ¿Qué es una función y por qué existe? 🪥

Imagina que cada vez que quieres lavarte los dientes tuvieras que explicar: «agarra el cepillo, pon pasta, mueve la mano arriba y abajo, enjuaga». Sería agotador repetir eso cada vez. En cambio, simplemente dices «lávate los dientes» y todos entienden el procedimiento completo.

Una función es exactamente eso: un bloque de código con un nombre que encapsula un procedimiento. Una vez que lo defines, puedes invocarlo las veces que quieras sin reescribir la lógica. 

def lavarse_dientes():
    print("Agarrar cepillo")
    print("Poner pasta")
    print("Cepillar 2 minutos")
    print("Enjuagar")

lavarse_dientes()  # "invocación" o "llamado" de la función
lavarse_dientes()  # se puede usar cuantas veces se quiera

📖 Vocabulario clave

  • Definir = escribir su código con def.
  • Invocar/llamar = ejecutar escribiendo su nombre seguido de ().
  • Parámetro = variable que la función espera recibir (en la definición).
  • Argumento = valor real que le pasas al invocarla.
def lavarse_dientes(minutos):  # "minutos" es un PARÁMETRO
    print(f"Cepillando por {minutos} minutos")

lavarse_dientes(2)  # "2" es el ARGUMENTO
1 return vs print — la confusión más común

Esta es la fuente del 80% de los errores de quienes recién aprenden funciones.

🖨️ print()

Muestra algo en pantalla. Comunicación con el humano. No le sirve al programa.

📬 return

Entrega un valor de vuelta a quien llamó. Comunicación entre partes del programa. El programa SÍ puede usar ese valor.

def sumar_print(a, b):
    print(a + b)  # solo IMPRIME, no entrega nada

def sumar_return(a, b):
    return a + b  # ENTREGA el resultado

resultado1 = sumar_print(3, 4)   # en pantalla aparece "7"
print(resultado1)                # pero esto imprime "None" !!

resultado2 = sumar_return(3, 4)  # no aparece nada en pantalla
print(resultado2)                # esto imprime "7"

¿Por qué pasa esto? Sin return, Python automáticamente asigna None. Por eso resultado1 termina siendo None.

🎯 Regla para el examen: si el programa necesita usar el resultado después → return. Si solo necesita mostrar algo → print.
2 Parámetros con valores por defecto

A veces queremos que un parámetro tenga un valor «de respaldo» si no se especifica.

def saludar(nombre, idioma="español"):
    if idioma == "español":
        print(f"Hola, {nombre}")
    elif idioma == "inglés":
        print(f"Hello, {nombre}")

saludar("Juan")              # usa "español" por defecto
saludar("John", "inglés")    # sobreescribe el valor por defecto

⚠️ Detalle importante: los parámetros con valor por defecto deben ir después de los que no lo tienen. def mal(a="x", b): da error.

3 Mutabilidad — CRÍTICO para el examen

Vas a tener UNA lista que vive durante toda la ejecución y muchas funciones que la modifican.

✅ Listas y Diccionarios (mutables)

Se pasan «por referencia». La función modifica el original.

❌ Números, Strings, Booleanos (inmutables)

Se pasan «por valor». La función recibe una copia.

# LISTA: el cambio SÍ se mantiene afuera
def agregar_fruta(lista_frutas):
    lista_frutas.append("manzana")
    # no hay return, y no hace falta

mis_frutas = ["pera", "uva"]
agregar_fruta(mis_frutas)
print(mis_frutas)  # ['pera', 'uva', 'manzana'] -> ¡se modificó!

# NÚMERO: el cambio NO se mantiene afuera
def intentar_cambiar(numero):
    numero = numero + 100
    # esto NO afecta la variable original

x = 5
intentar_cambiar(x)
print(x)  # sigue siendo 5
🎯 Para el examen: cuando definas la función que agrega un estudiante, recibirás la lista como parámetro, le harás .append(), y no necesitas retornar la lista — el cambio ya quedó hecho.
4 Funciones de validación — patrón «sí o no»

Responde una pregunta booleana: ¿cumple la condición? Nombre típico: es_, tiene_, valida_. Siempre retorna True o False.

✨ Pythónica

def es_mayor_de_edad(edad):
    return edad >= 18

📝 Explícita

def es_mayor_de_edad(edad):
    if edad >= 18:
        return True
    else:
        return False

Ambas producen exactamente lo mismo. Usa la que entiendas mejor. Lo importante es reconocer las dos formas.

5 Búsqueda — patrón «posición o -1»

Uno de los patrones más importantes del examen. Recorres una lista buscando algo. Si lo encuentras, retornas la posición. Si no, retornas -1 (señal de «no encontrado»).

def buscar_posicion(lista, valor_buscado):
    for i in range(len(lista)):
        if lista[i] == valor_buscado:
            return i  # encontramos! salimos inmediatamente
    return -1  # si el for terminó sin encontrar nada

⚡ ¿Por qué return corta el ciclo? Porque return no solo entrega un valor, sino que termina la ejecución de la función inmediatamente.

Forma alternativa con enumerate():

def buscar_posicion_v2(lista, valor_buscado):
    for indice, valor in enumerate(lista):
        if valor == valor_buscado:
            return indice
    return -1

Ambas versiones hacen lo mismo. enumerate() es más limpio cuando necesitas tanto el índice como el valor. Conocer ambas te prepara para el examen.

6 Separación de responsabilidades

Cada función debería hacer UNA sola cosa y hacerla bien.

La función de búsqueda tiene UNA responsabilidad: encontrar y reportar dónde está algo. NO es su responsabilidad decidir qué hacer con esa información.

La misma función de búsqueda se reutiliza para cosas distintas:

  • Para «Buscar estudiante» → si encuentra, muestra los datos.
  • Para «Eliminar estudiante» → si encuentra, lo elimina.

Si la búsqueda ya tuviera incrustada la lógica de «mostrar datos», no podrías reutilizarla para eliminar. Al retornar solo la posición (o -1), el programa principal decide qué hacer según el contexto.

7 Reutilizar una función dentro de otra

Una función puede llamar a otra. Es la base de la organización modular.

def buscar_posicion(lista, valor):
    for i in range(len(lista)):
        if lista[i] == valor:
            return i
    return -1

def eliminar(lista, valor):
    posicion = buscar_posicion(lista, valor)  # reutilizamos
    if posicion != -1:
        lista.pop(posicion)
        print("Eliminado correctamente")
    else:
        print("No se encontró el elemento")

Si mejoras buscar_posicion, automáticamente eliminar también mejora.

8 Recorrer y modificar TODOS los elementos

Aplicar una regla a cada elemento de la lista, sin excepción.

def aplicar_descuento(lista_precios):
    for i in range(len(lista_precios)):
        lista_precios[i] = lista_precios[i] * 0.9  # 10% de descuento

# Con diccionarios: acceder y modificar un campo específico
def marcar_todos_revisados(lista_productos):
    for producto in lista_productos:
        producto["revisado"] = True

💡 Nota sutil: for producto in lista funciona para modificar diccionarios porque producto es una referencia al diccionario real (Concepto 3). Si la lista contuviera números, necesitarías índices.

9 El Dispatcher — «central telefónica»

Dispatcher viene de to dispatch (despachar). Como un operador de central telefónica que recibe una llamada y la dirige al lugar correcto.

opcion = leer_opcion()

if opcion == 1:
    agregar_estudiante(lista)
elif opcion == 2:
    buscar_estudiante(lista)
elif opcion == 3:
    eliminar_estudiante(lista)
elif opcion == 6:
    print("Adiós")
    break

🔮 Alternativa avanzada (opcional): diccionario de funciones

acciones = {
    1: opcion_agregar,
    2: opcion_buscar,
}

opcion = 1
if opcion in acciones:
    acciones[opcion]()  # se ejecuta con los paréntesis
else:
    print("Opción inválida")

Para el examen, if/elif/else es perfectamente válido y suficiente.

10 while True + break — la estructura de un menú

Un menú se repite indefinidamente hasta que el usuario decide salir.

while True:
    mostrar_menu()
    opcion = leer_opcion()

    if opcion == 6:
        print("Adiós")
        break  # rompe el ciclo, el programa continúa después del while

    # ... resto de las opciones

¿Por qué no while opcion != 6? Técnicamente se puede, pero tendrías que inicializar opcion con algún valor artificial. while True + break es el patrón estándar para este caso.

11 Validar entradas — «pedir hasta que sea válido»

El patrón: pedir, validar, y si no es válido, volver a pedir.

Con .isdigit()

def pedir_edad_valida():
    while True:
        entrada = input("Edad: ")
        if entrada.isdigit() and int(entrada) > 0:
            return int(entrada)
        else:
            print("Edad inválida")

Con try/except

def pedir_edad_valida_v2():
    while True:
        entrada = input("Edad: ")
        try:
            edad = int(entrada)
            if edad > 0:
                return edad
            else:
                print("Mayor que 0")
        except ValueError:
            print("No es número")
🎯 Para el examen: elige UNA estrategia y sé consistente en todas tus validaciones.
12 Validar contra texto vacío o solo espacios

🔧 Versión manual

def tiene_contenido_v1(texto):
    for caracter in texto:
        if caracter != " ":
            return True
    return False

✨ Versión con .strip()

def tiene_contenido_v2(texto):
    return texto.strip() != ""

.strip() retorna una copia del string sin espacios al inicio ni al final. " ".strip() → ""

La versión manual desarrolla tu capacidad de «pensar como el computador». La versión con .strip() es lo que usarías en código real. Saber ambas es valioso.

13 Validar números decimales en un rango 
def es_nota_valida(nota):
    return isinstance(nota, (int, float)) and 1.0 <= nota <= 7.0
  • isinstance(valor, tipo) retorna True si valor es del tipo indicado. La tupla (int, float) permite entero o decimal.
  • 1.0 <= nota <= 7.0 es una «comparación encadenada» = nota >= 1.0 and nota <= 7.0
14 Contar elementos que cumplen una condición

📝 Con contador

def contar_aprobados_v1(lista):
    contador = 0
    for est in lista:
        if est["aprobado"] == True:
            contador = contador + 1
    return contador

✨ Con sum()

def contar_aprobados_v2(lista):
    return sum(
        1 for est in lista
        if est["aprobado"]
    )

Produce un 1 por cada aprobado y sum() los suma.

Cada pedido es un diccionario con:

  • "cliente": nombre del cliente.
  • "items": una lista de diccionarios, cada uno con "nombre_plato" y "precio".
  • "propina_porcentaje": decimal entre 0 y 30.
  • "estado": string — "pendiente", "en preparación", "entregado".

Nuevos retos:

  1. Listas dentro de diccionarios dentro de listas (estructuras anidadas): necesitas un for dentro de otro for = anidamiento de ciclos.
  2. Sub-ciclo de captura: al agregar, un ciclo «¿desea agregar otro plato? (s/n)» agregando cada plato a "items".
  3. Búsqueda con múltiples resultados: buscar_por_cliente() retorna una lista de posiciones (puede estar vacía).
  4. Cálculo compuesto: calcular_total_pedido() suma precios de todos los items y aplica propina.
  5. Actualización condicional compleja: pedidos "pendiente" con más de 3 items pasan a "en preparación".
🔍 Antes de empezar: busca «nested loops» y mira un ejemplo donde se recorra una lista de diccionarios con listas. Dibuja en papel la estructura de un pedido con 2-3 items: pedido["items"][0]["nombre_plato"].

🌱 Si «casi no entiendes nada»

  1. No saltes el Mini-taller. Cada concepto tiene un número — si en un ejercicio te trabas, vuelve al concepto referenciado.
  2. Ejecuta TODO. No leas el código y asumas que entiendes — escríbelo, córrelo, cambia valores y observa qué pasa.
  3. Las preguntas «¿Pregúntate?» e «¿Investiga?» no son opcionales — son las que construyen la comprensión real, no solo la memorización del patrón.

⚡ Si «te resulta fácil»

  1. No te saltes las preguntas de «Investiga» — son las que te llevan a conceptos que probablemente no conoces aún (generadores, .get(), excepciones específicas, mutabilidad profunda).
  2. En los ejercicios con «dos versiones», domina ambas — en el examen o en una entrevista te pueden pedir explicar la alternativa.
  3. El Ejercicio 31 es tu verdadero desafío — intenta resolverlo sin pistas adicionales.
