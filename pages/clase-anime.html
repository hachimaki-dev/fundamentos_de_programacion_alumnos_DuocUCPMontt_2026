Activación Mental 🧠

Antes de enfrentarnos al desarrollo completo del sistema AniStream, asegúrate de dominar estos 3 conceptos clave.

1Acceso por Posición

Si tienes catalogo = {'AN001': [9990, 75]}, ¿cómo obtienes el número 75?

Respuesta mental: Accedes primero a la clave del diccionario y luego al índice de la lista. En código sería: catalogo['AN001'][1].
2Diccionarios Paralelos

Si tienes series y catalogo que comparten la misma clave (el código de la serie). ¿Cómo iterarías sobre ambos al mismo tiempo?

Respuesta mental: No necesitas un bucle doble. Basta iterar sobre las claves de uno de los diccionarios (ej: for cod in series:) y usar esa misma variable cod para extraer valores del otro diccionario (catalogo[cod]).
3Try/Except vs If

¿Cuál es la diferencia entre usar if para validar un género (ej: "Accion") y usar try/except ValueError para validar un precio?

Respuesta mental: Usamos if para validar formatos de texto o reglas de negocio (ej: si está dentro de una lista de opciones permitidas). Usamos try/except cuando intentamos convertir un tipo de dato (como un string a entero usando int()) para evitar que el programa colapse si el usuario ingresa letras en lugar de números.

Instrucciones 🎯

La plataforma de streaming AniStream requiere un programa en Python para administrar su catálogo de series de anime y la disponibilidad de episodios por serie. Todo el comportamiento del sistema debe organizarse en funciones bien definidas. El programa incluye un menú interactivo, validaciones de entrada y una separación clara entre la lógica de cada función y las decisiones del programa principal.

1. Datos que debe manejar el sistema 📦

💡 Aclaración Pedagógica sobre el Diseño de Datos

En este ejercicio, los valores de los diccionarios son listas ordenadas por posición en lugar de diccionarios anidados (por ejemplo, debes acceder a catalogo['AN001'][1] en lugar de catalogo['AN001']['episodios']).
Aunque en proyectos reales suele ser más robusto y elegante usar diccionarios o clases para evitar depender de "posiciones mágicas", este formato estructurado por índices es requerido específicamente por las rúbricas del Examen Transversal. Es fundamental que practiques la extracción y modificación de datos accediendo directamente por sus posiciones ([0], [1], etc.) tal como se describe a continuación.

El sistema trabaja con dos diccionarios relacionados, ambos identificados por el mismo código de serie como clave. Estos diccionarios deben existir desde que el programa inicia y permanecer disponibles durante toda la ejecución.

Diccionario series

Contiene la información descriptiva de cada anime. La clave es el código de la serie y el valor es una lista con los siguientes campos, en este orden:

Campo Qué representa Restricciones de validación
"titulo" Nombre de la serie No debe contener solo espacios en blanco ni estar vacío
"genero" Género de la serie No debe contener solo espacios en blanco ni estar vacío
"estudio" Estudio de animación No debe contener solo espacios en blanco ni estar vacío
"clasificacion" Clasificación de audiencia Debe ser exactamente 'G', 'PG' o 'M'
"subtitulado" Indica si está subtitulada El usuario ingresa 's' o 'n'. El sistema lo convierte a True o False
"pais_origen" País de origen No debe contener solo espacios en blanco ni estar vacío

Diccionario catalogo

Contiene la información operativa de cada serie. La clave es el mismo código y el valor es una lista con los siguientes dos campos:

Campo Qué representa Restricciones de validación
"precio" Precio mensual en pesos Número entero mayor que cero
"episodios" Cantidad de episodios disponibles Número entero mayor o igual a cero

2. Lo que debe hacer el sistema ⚙️

El sistema se controla desde un menú interactivo. Si el usuario ingresa un valor inválido, el sistema muestra "Debe seleccionar una opción válida" y vuelve a mostrar el menú. 

========== MENÚ PRINCIPAL ==========
1. Episodios por género
2. Búsqueda de series por rango de precio
3. Actualizar precio de serie
4. Agregar serie
5. Eliminar serie
6. Salir
=====================================

Detalle de las Opciones del Menú:

1Episodios por género

El sistema solicita el nombre de un género. La búsqueda no distingue entre mayúsculas y minúsculas. El sistema recorre series identificando todas las series de ese género, y luego extrae la cantidad de episodios de catalogo para acumularla en un total.

Implementación: Define episodios_genero(genero). Recibe el género, no retorna ningún valor y muestra el resultado directamente en pantalla.
2Búsqueda de series por rango de precio

Solicita un precio mínimo y máximo. Recorre catalogo y construye una lista con las series que cumplan ambas condiciones: (a) precio dentro del rango, y (b) tengan episodios > 0. El formato es "Titulo--Codigo" y se muestran ordenados alfabéticamente por título. Si no hay, muestra un mensaje de error.

Implementación: En el programa principal, exige try/except para validar que sean números enteros. Luego llama a busqueda_precio(p_min, p_max) que no retorna nada e imprime los resultados.
3Actualizar precio de serie

Solicita el código y el nuevo precio. Si existe en catalogo, actualiza su precio. Permite repetir el proceso preguntando: "¿Desea actualizar otro precio (s/n)?".

Implementación: Define actualizar_precio(codigo, nuevo_precio). Retorna True o False. El programa principal decide qué mostrar. La validación del código no debe distinguir mayúsculas/minúsculas.
4Agregar serie

Solicita todos los datos y los valida individualmente. Si todo es válido y el código no existe previamente, agrega el registro en ambos diccionarios.

Implementación: Define una función de validación independiente para cada campo (que retornan True o False, sin prints). Llama a agregar_serie(codigo, titulo, genero, estudio, clasificacion, subtitulado, pais_origen, precio, episodios) si todo es válido, la cual retorna True/False.
5Eliminar serie

Solicita el código. Si existe, lo elimina de ambos diccionarios.

Implementación: Define eliminar_serie(codigo). Retorna True o False, el programa principal imprime los mensajes. Case-insensitive.
